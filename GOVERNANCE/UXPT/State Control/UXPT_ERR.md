# UXPT_ERR — Error Handling System

---

## UXPT_ERR_1 — 인라인 에러

### 개요

입력 과정에 발생하는 오류는 바로 해당 위치에서 수정 가능하도록 안내해야 합니다.

### 규칙 — UXPT_ERR_1_RULE_1

오류는 입력 필드 인접 영역에 표시해야 합니다.

| 항목 | 내용 |
|------|------|
| 원칙 | 고객 시선이 에러에 바로 닿아야 합니다. |
| 설명 | 에러 메시지 표시 시 고객 흐름을 해쳐야 하지 않고, 해당 필드를 다시 찾도록 해서는 안 됩니다. |

### 규칙 — UXPT_ERR_1_RULE_2

문제 원인을 명확히 설명해야 합니다.

| 항목 | 내용 |
|------|------|
| 원칙 | 에러 메시지는 원인이 무엇인지 명확히 설명해야 합니다. |
| 금지 | 단순 `'오류가 나타났습니다'` 처럼 어떤 필드의 어떤 문제인지 알 수 없는 메시지 금지 |

### 규칙 — UXPT_ERR_1_RULE_3

수정 방법을 함께 제공해야 합니다.

| 항목 | 내용 |
|------|------|
| 원칙 | 고객이 혼란스러워하거나 포기하지 않도록 안내해야 합니다. |
| 설명 | 에러 메시지 아래에 수정 해결 방법을 제시해야 합니다. |

### Do / Don't

| Do ✅ | Don't ❌ |
|-------|---------|
| 문제 필드 바로 아래에 원인과 수정 방법을 함께 노출한다. | 상단 통합 알림으로만 표시하여 어떤 필드가 문제인지 고객이 직접 찾게 만든다. |

#### Do 예시
```
홍길동
010-1234-5678
*********
⚠ 비밀번호를 8자 이상, 숫자, 특수문자를 포함해 입력해 주세요.
[제출하기]
```

#### Don't 예시
```
⚠ 입력값에 오류가 있어요.
홍길동 / 010-1234-5678 / *********
[제출하기]
```

## UXPT_ERR_2 — 결과 없음 상태

### 개요

데이터가 없는 경우에는 이유와 다음 행동을 명확히 제시해야 합니다.

### 규칙 — UXPT_ERR_2_RULE_1

결과가 없는 이유를 함께 설명해야 합니다.

| 항목 | 내용 |
|------|------|
| 원칙 | 결과가 없는 이유를 고객이 이해할 수 있도록 설명해야 합니다. |
| 금지 | `'결과가 없습니다'` 단독 노출로 고객이 상황을 직접 해석하게 만드는 것 금지 |

### 규칙 — UXPT_ERR_2_RULE_2

재시도 또는 대체 행동을 제공해야 합니다.

| 항목 | 내용 |
|------|------|
| 원칙 | 결과 없음 상태에서 대안을 제시하고, 재시도 이유와 방법을 함께 안내해야 합니다. |
| 설명 | 검색어 수정 방안을 제안하고, 인근 결과나 유사 항목도 함께 안내합니다. |

### 규칙 — UXPT_ERR_2_RULE_3

고객이 다음 행동을 고민하지 않도록 해야 합니다.

| 항목 | 내용 |
|------|------|
| 원칙 | 이탈하지 않도록 시스템이 다음 행동을 안내해야 합니다. |
| 설명 | 결과 없음 상태에서 링크나 CTA를 제공하여 고객이 빈 화면에 머물지 않도록 합니다. |

### Do / Don't

| Do ✅ | Don't ❌ |
|-------|---------|
| 결과가 없는 이유를 설명하고, 같은 범주의 대체안으로 탐색을 이어가게 한다. | `'검색 결과 없음'` 단독 표시로 텅 빈 화면에 한 줄 메시지만 노출한다. |

#### Do 예시
```
근처 '스타벅스' 매장을 찾지 못했어요
500m 내에 매장이 없어요
[근처 카페 더보기]
```

## UXPT_ERR_3 — 시스템 에러

### 개요

시스템 오류 발생 시 고객이 불안하지 않도록 상황과 해결 경로를 명확히 안내해야 합니다.

### 규칙 — UXPT_ERR_3_RULE_1

오류 상황을 명확히 설명해야 합니다.

| 항목 | 내용 |
|------|------|
| 원칙 | 고객 언어로 설명해야 합니다. |
| 설명 | `'잠시 후 다시 시도해 주세요'` 처럼 고객이 상황을 이해하고 다음 행동을 알 수 있는 표현을 사용합니다. |

### 규칙 — UXPT_ERR_3_RULE_2

고객 책임이 아님을 전달해야 합니다.

| 항목 | 내용 |
|------|------|
| 원칙 | 고객이 잘못이라고 오해하지 않도록 해야 합니다. |
| 금지 | 에러 코드 단독 노출로 고객이 본인 문제인지 시스템 문제인지 혼동하게 만드는 것 금지 |

### 규칙 — UXPT_ERR_3_RULE_3

복귀 또는 대체 경로를 제공해야 합니다.

| 항목 | 내용 |
|------|------|
| 원칙 | 다시 시도 또는 다음 행동을 제시합니다. |
| 설명 | 일시적인 경우 다시 시도하기와 홈으로 돌아가기를 함께 제시합니다. |

### Do / Don't

| Do ✅ | Don't ❌ |
|-------|---------|
| 결과가 없는 이유를 설명하고 대체 경로를 제공한다. | `Error 500` 등 기술 코드만 노출하여 고객이 본인 잘못이라 오해하게 만든다. |

#### Do 예시
```
일시적으로 접속할 수 없어요
잠시 후 다시 시도해 주세요.
[다시 시도] [홈으로]
```

## UXPT_ERR_4 — AI 실패

### 개요

AI 결과를 제공하지 못한 경우에는 재시도 방법을 안내해야 합니다.

### 규칙 — UXPT_ERR_4_RULE_1

실패 원인을 간단히 설명해야 합니다.

| 항목 | 내용 |
|------|------|
| 원칙 | 질문이 이해되지 않은 이유 등을 설명하고 다음 행동을 안내해야 합니다. |

### 규칙 — UXPT_ERR_4_RULE_2

재질문 또는 다른 입력 방식을 유도해야 합니다.

| 항목 | 내용 |
|------|------|
| 원칙 | 질문이 모호하거나 인식이 불가한 경우 대체 입력 방식을 제공해야 합니다. |

### 규칙 — UXPT_ERR_4_RULE_3

다시 시도할 수 있는 경로를 제공해야 합니다.

| 항목 | 내용 |
|------|------|
| 원칙 | 내용을 다시 입력하도록 유도하거나 다른 입력 방식을 시도할 수 있는 경로를 제공해야 합니다. |
| 금지 | 실패 메시지만 노출하고 다음 행동 경로 없이 멈추는 것 금지 |

### Do / Don't

| Do ✅ | Don't ❌ |
|-------|---------|
| 음성 재시도·직접 입력·상담 연결 등 대체 입력 방식을 제공한다. | 실패만 알리고 다시 시도하거나 다른 입력 방식으로 전환할 경로가 없다. |

#### Do 예시
```
[T Agent]
이해하지 못했어요.
다시 입력해 주세요.
[Action]
```
