# UXPT_LOD — Loading & Waiting System

---

## UXPT_LOD_1 — 부분 로딩

### 개요

일부만 갱신되는 경우에는 전체 로딩을 지양하고 변경 영역만 로딩 상태로 표현해야 합니다.

### 규칙 — UXPT_LOD_1_RULE_1

버튼·리스트 일부 등 특정 영역만 변경되는 경우에만 사용해야 합니다.

| 항목 | 내용 |
|------|------|
| 원칙 | 전체 갱신에는 반드시 전체 로딩을 사용해야 합니다. |
| 금지 | 결과 전체가 바뀌는 상황에 부분 로딩을 사용하면 고객이 결과가 다 왔는지 전부 갱신된 것인지 알 수 없습니다. |

### 규칙 — UXPT_LOD_1_RULE_2

기존 데이터는 유지하고 변경되는 영역만 로딩 상태로 전환해야 합니다.

| 항목 | 내용 |
|------|------|
| 원칙 | 고객이 맥락을 잃지 않도록 해야 합니다. |
| 금지 | 처리 중 기존 리스트 전체가 사라지고 일부만 갱신되면, 고객이 맥락을 잃고 다시 확인해야 합니다. |

### 규칙 — UXPT_LOD_1_RULE_3

무엇이 갱신되고 있는지 고객이 즉시 인지할 수 있어야 합니다.

| 항목 | 내용 |
|------|------|
| 원칙 | 로딩 인디케이터의 대상이 명확히 드러나야 합니다. |
| 금지 | 특정 영역에만 스피너가 표시되어도 고객이 리스트를 갱신하는 것인지 처리가 진행 중인지 구분하지 못하는 구조 금지 |

### Do / Don't

| Do ✅ | Don't ❌ |
|-------|---------|
| 갱신되는 영역(예: 다운로드 버튼)만 인라인 스피너로 전환하고 그 외 페이지·스크롤은 그대로 유지한다. | 버튼 클릭 한 번에 화면 전체가 로딩되어 보던 위치·스크롤·맥락을 모두 잃게 만든다. |

## UXPT_LOD_2 — 스켈레톤 UI

### 개요

데이터 로딩 이전에는 스켈레톤을 활용하여 결과 형태를 예측할 수 있도록 해야 합니다.

### 규칙 — UXPT_LOD_2_RULE_1

리스트·상세 등 콘텐츠 구조가 명확한 영역에서 사용해야 합니다.

| 항목 | 내용 |
|------|------|
| 금지 | 구조가 불명확한 영역에서는 사용하지 않습니다. |
| 설명 | 로딩하는 데이터가 어떤 형태일지 예측 가능한 콘텐츠 구조에서만 사용하고, 그 외에는 대체 패턴을 사용합니다. |

### 규칙 — UXPT_LOD_2_RULE_2

실제 UI와 동일한 레이아웃으로 구성해야 합니다.

| 항목 | 내용 |
|------|------|
| 원칙 | 스켈레톤과 실제 콘텐츠의 레이아웃이 달라서는 안 됩니다. |
| 금지 | 스켈레톤과 실제 콘텐츠의 구조가 다르면 전환 시 레이아웃 점프가 발생하고 고객이 혼란을 느낍니다. |

### 규칙 — UXPT_LOD_2_RULE_3

로딩 이후 레이아웃이 변경되지 않도록 유지해야 합니다.

| 항목 | 내용 |
|------|------|
| 원칙 | 스켈레톤 전환 시 레이아웃 점프를 방지해야 합니다. |
| 금지 | 스켈레톤에서 2단 리스트로 전환되면 고객이 이미 봤던 처음 위치를 다시 확인해야 하는 상황 금지 |

### Do / Don't

| Do ✅ | Don't ❌ |
|-------|---------|
| 실제 콘텐츠 자리에 동일한 레이아웃의 회색 박스를 미리 배치 → 로드 후 자연스럽게 채워지며 레이아웃 점프가 없다. | 빈 화면 + 중앙 스피너로 결과 형태를 알 수 없고 로드 후 콘텐츠가 갑자기 펼쳐지며 레이아웃이 점프한다. |

## UXPT_LOD_3 — 전체 로딩

### 개요

전체 데이터가 변경되는 경우에는 처리 상황과 진행 상태를 명확히 안내해야 합니다.

### 규칙 — UXPT_LOD_3_RULE_1

페이지 전환·결제 등 전체 상태 변경 시에만 사용해야 합니다.

| 항목 | 내용 |
|------|------|
| 금지 | 일부만 갱신되는 경우에 전체 로딩을 사용하면 고객이 이미 로딩된 것도 사라진다고 인식합니다. |

### 규칙 — UXPT_LOD_3_RULE_2

처리 중에는 이전 화면으로 돌아갈 수 없음을 명확히 전달해야 합니다.

| 항목 | 내용 |
|------|------|
| 원칙 | 고객이 처리 완료를 기다려야 한다는 것을 명시하고, 현재 처리 상황을 안내해야 합니다. |
| 금지 | 결제 처리 중 단순 대기 상태만 표시하면 고객이 처리 중인지 이미 완료된 것인지 알 수 없습니다. |

### 규칙 — UXPT_LOD_3_RULE_3

처리 완료 직후 결과 화면으로 즉시 전환해야 합니다.

| 항목 | 내용 |
|------|------|
| 금지 | 완료 이후 화면 전환이 지연되면 고객이 처리 여부를 알 수 없습니다. |
| 설명 | 완료 결과 화면으로의 전환이 2초 이상 지연되면 고객이 처리 중인지 판단하지 못하고 기다림을 포기하거나 이탈할 수 있습니다. |

### Do / Don't

| Do ✅ | Don't ❌ |
|-------|---------|
| 정렬·필터처럼 일부만 바뀌는 경우 변경 영역만 로딩 상태로 전환하고 나머지 화면은 유지한다. | 일부만 바뀌는 상황에 전체 화면을 차단한다. |

## UXPT_LOD_4 — AI '생각중' 상태

### 개요

AI 분석 처리를 수행할 때 사용하는 전용 패턴입니다. 맥락과 시이 함께 분해되어, 고객이 무엇을 기다리고 있는지를 명확히 인지하게 해야 합니다.

### 규칙 — UXPT_LOD_4_RULE_1

일반 로딩과 구분되는 AI 전용 패턴으로 표시해야 합니다.

| 항목 | 내용 |
|------|------|
| 금지 | 스피너만 표시하면 처리 주체를 구분하기 어려워 고객이 AI 처리임을 인지하지 못합니다. |
| 설명 | AI 처리 중임을 상징하는 시각 패턴과 텍스트를 함께 사용해야 합니다. |

### 규칙 — UXPT_LOD_4_RULE_2

AI가 현재 수행 중인 작업을 구체적인 텍스트로 함께 표시해야 합니다.

| 항목 | 내용 |
|------|------|
| 원칙 | `'AI 처리 중'` 대신 `'사용 패턴 분석 중'`, `'요금제 추천 중'` 처럼 처리 내용을 명확히 표시해야 합니다. |
| 설명 | 복합 분석 시에는 상위 기준만 표시하고 세부 단계는 전환해 가며 노출합니다. |

### 규칙 — UXPT_LOD_4_RULE_3

처리 소요가 길어질 경우 중단 옵션을 제공해야 합니다.

| 항목 | 내용 |
|------|------|
| 원칙 | 고객이 원하지 않는 진행 중에 중단할 수 있어야 합니다. |
| 기준 | 분석이 3초 이상 지속되면 `'분석 중단하기'` 버튼이 노출되어야 합니다. |
| 금지 | 중단 옵션 없이 계속 기다려야 하거나 다른 방식으로 시도하고 싶을 때 이탈 외에 방법이 없는 구조 금지 |

### Do / Don't

| Do ✅ | Don't ❌ |
|-------|---------|
| AI가 무엇을 입력으로 분석해 어떤 결과를 보여줄지를 함께 명시한다. | 의미 없는 애니메이션만 표시하여 무엇을 하는지 알 수 없게 만든다. |

### 시나리오 — 상황별 적용 방식

| 시나리오 | 표시 내용 | 중단 옵션 |
|----------|----------|----------|
| 사용 패턴 분석 | `'사용 패턴을 분석하고 있어요'` + `'최근 3개월 데이터를 기반으로 가장 적합한 요금제를 찾고 있어요.'` | 분석 중단하기 (3초 이상 시) |
| 해지 처리 중 | `'해지 요청을 접수하고 있어요'` | 해지 중단하기 |
| 번호 인식 완료 | `'번호를 인식했어요, 잠시만 기다려 주세요.'` | — |
