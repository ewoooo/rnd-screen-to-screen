# UXPT_RCV — Recovery Flow System

---

## UXPT_RCV_1 — 재시도 / 대체 경로

### 개요

실패 발생 시 고객이 즉시 다음 행동을 수행할 수 있도록 최적의 경로를 제시해야 합니다.

### 규칙 — UXPT_RCV_1_RULE_1

재시도와 대체 경로를 함께 제공해야 합니다.

| 항목 | 내용 |
|------|------|
| 금지 | 실패 화면에서 단일 `'확인'` 버튼만 제공하면 고객이 무엇을 해야 할지 스스로 판단해야 해 이탈이 발생합니다. |

### 규칙 — UXPT_RCV_1_RULE_2

우선 실행 경로를 명확히 제시해야 합니다.

| 항목 | 내용 |
|------|------|
| 원칙 | `'다시 시도하기'`·`'상담 연결'` 등 실행 경로를 Primary로 시이 추천하고 다음 행동을 제시해야 합니다. |
| 방식 | 일시적 오류는 `'다시 시도하기'`를 Primary에 놓고 상담 연결을 Secondary로 배치합니다. |

### 규칙 — UXPT_RCV_1_RULE_3

필요 시 상담 연결을 제공해야 합니다.

| 항목 | 내용 |
|------|------|
| 원칙 | 재도 시도가 의미 없는 상황에서는 재시도 대신 상담 연결을 경로로 제공해야 합니다. |

### Do / Don't

| Do ✅ | Don't ❌ |
|-------|---------|
| 우선 경로와 대체 경로를 함께 제공한다. | `'확인'` 버튼 단일 노출로 다음 행동을 고객이 직접 탐색하게 만든다. |

#### Do 예시
```
⚠ 결제에 실패했습니다
[다시 시도] ← Primary
[다른 카드로 결제] ← Secondary
```

#### Don't 예시
```
⚠ 결제에 실패했습니다
[확인]
```

## UXPT_RCV_2 — 상태 복원

### 개요

재진입 시 이전 상태를 그대로 이어서 사용할 수 있도록 복원해야 합니다.

### 규칙 — UXPT_RCV_2_RULE_1

입력값과 선택 상태를 유지해야 합니다.

| 항목 | 내용 |
|------|------|
| 원칙 | 실패 시 고객이 다시 입력하지 않도록 시스템이 보존해야 합니다. |
| 방식 | 기기 교체 도중 이탈 후 재진입해도 이전에 입력한 정보가 그대로 유지되어야 합니다. |

### 규칙 — UXPT_RCV_2_RULE_2

재진입 시 이어서 진행 경로를 제공해야 합니다.

| 항목 | 내용 |
|------|------|
| 원칙 | 복원된 상태에 바로 다음 단계로 갈 수 있는 CTA를 제시합니다. |
| 방식 | 복원 화면 상단에 `'이어서 진행하기'` 버튼이 먼저 표시되어야 합니다. |

### 규칙 — UXPT_RCV_2_RULE_3

복원이 불가능한 경우에는 명확히 안내해야 합니다.

| 항목 | 내용 |
|------|------|
| 원칙 | 복원 불가 사유를 안내하고 새 시작 경로를 제공해야 합니다. |
| 방식 | `'이전 신청은 24시간이 지나 자동 만료되었습니다. 새로 신청해 주세요'` 처럼 이유와 함께 새로 시작하는 경로를 안내합니다. |

### Do / Don't

| Do ✅ | Don't ❌ |
|-------|---------|
| 재진입 즉시 입력값·선택·단계가 그대로 살아 있어 이어서 진행 가능하다. | 재진입 시 작성 중이던 내용이 사라지고 처음부터 시작하게 만든다. |

#### Do 예시
```
작성중인 내용을 불러왔어요
마지막 작성 23분 전

[2/4 단계]
홍길동
010-1234-5678
*********
[이어서 진행하기]
```
