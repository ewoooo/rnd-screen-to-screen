# UXPT_NAV — Navigation

---

## UXPT_NAV_1 — GNB

> **패턴 태그**: Borderless · Frictionless

상단 위계 구조를 제공하는 고정 네비게이션입니다. 어디로 이동하더라도 현재 위치를 명확히 인지하게 해야 합니다.

### 규칙

| 규칙 ID | 핵심 제약 | 설명 | 예시 |
|---------|---------|------|------|
| `UXPT_NAV_1_RULE_1` | 최상위 메뉴 3~5개 제한 | 고객이 복잡하지 않게 구성한다. AI 에이전트도 동일 기준을 따라야 한다. | 기능 단위 메뉴 7개 이상 나열 금지 |
| `UXPT_NAV_1_RULE_2` | 선택 탭 상태 변화 필수 | 선택된 탭은 컬러, 아이콘, 라벨 상태 변화로 반드시 구분해야 한다. 활성 하이라이트 없이 비활성 구분만 하면 고객이 현재 위치를 확인하기 위해 전체를 훑어야 한다. | 비활성 탭과 활성 탭의 컬러·굵기 명확히 구분 |
| `UXPT_NAV_1_RULE_3` | 핵심 태스크를 주 사용 손 방향 배치 | 단순 나열이 아니라, 빈도/도달/중요도를 기준으로 위치를 정해야 한다. 자주 사용하는 기능은 엄지손가락이 스치게 하단 중앙에 위치한다. | 홈·혜택·쇼핑·마이 4탭 구성 |
| `UXPT_NAV_1_RULE_4` | 개인화 적용 시 GNB 구조 기준 불변 | 서비스마다 고객마다 달라지더라도 구조와 서체는 일관되지 않으면 안 된다. | 개인화 메뉴 추가 시에도 탭 수·위치 고정 |

### Do / Don't

| Do ✅ | Don't ❌ |
|-------|---------|
| **의도 중심 4개 메뉴** — 고객 빈도·중요도 기준으로 압축. 선택된 탭은 컬러와 굵기로 명확히 강조된다. | **기능 단위 메뉴 7개 이상 나열** — 현재 위치를 시각적으로 구분하기 어렵고, 고객이 매번 메뉴를 해석해야 한다. |

### 시나리오 — 상황별 적용 방식

| 상황 | GNB 탭 구성 | 제약 |
|------|-----------|------|
| 기본 구조 | 홈 / 혜택 / 쇼핑 / 마이 (4개) | 탭 순서와 위치는 어느 화면에서도 고정되어야 한다. |
| 탭 이동 시 | 현재 탭 하이라이트 즉시 변경 | 탭 이동 후에도 GNB 구조와 위치는 고정 유지. |
| AI 에이전트 환경 | 동일 3~5개 탭 기준 적용 | AI 에이전트 화면에서도 GNB 메뉴 수와 구조 기준 동일 준수. |

## UXPT_NAV_2 — 뒤로 가기

> **패턴 태그**: Frictionless

뒤로 가기는 고객을 전 맥락으로 되돌리는 이동 장치입니다. 탐색/비교/완료를 지원하는 복귀 구조여야 합니다.

### 규칙

| 규칙 ID | 핵심 제약 | 설명 | 예시 |
|---------|---------|------|------|
| `UXPT_NAV_2_RULE_1` | 직전 화면·단계로만 이동 | 동일 네비게이션이 탭, 목록, 이전으로 다양하게 이동하지 않아야 한다. 탭에서 뒤로 가기를 누를 경우 앱 종료로 이동하면 고객이 이전 맥락을 다시 찾아야 한다. | 탭 뒤로 가기 → 앱 종료 금지 |
| `UXPT_NAV_2_RULE_2` | 리스트→상세 복귀 시 위치·필터 유지 | 고객이 동일 조건을 다시 설정하다 다시 탐색하지 않도록 해야 한다. 상품을 스크롤하며 확인하고 나서 뒤로 갈 때 이전 위치로 돌아가기 위해 동일 스크롤을 반복하는 상황은 금지. | 스크롤 위치·정렬·필터 상태 복원 |
| `UXPT_NAV_2_RULE_3` | 다단계 태스크에서는 이전 입력 단계로 이동 | 뒤로 가기가 전 리스트 전체를 종료하면 고객이 모든 입력을 다시 해야 한다. 다단계 태스크에서는 반드시 직전 단계로 돌아가야 한다. | 3단계 입력 중 뒤로 가기 → 2단계로 이동 (처음 단계로 이동 금지) |
| `UXPT_NAV_2_RULE_4` | 뒤로 가기 후 이전 입력 보존 | 화면에서 뒤로 가기가 되면 이전에 이미 입력한 정보가 보존되어야 한다. iOS 스와이프 등 OS 기본 복귀 동작도 동일한 규칙을 따라야 하며 잔여 프로세스가 사라지지 않도록 통제해야 한다. | iOS 스와이프 복귀 → 전체 태스크 종료 금지 |

### Do / Don't

| Do ✅ | Don't ❌ |
|-------|---------|
| **위치·필터 유지** — 상세에서 뒤로 갈 시 이전에 보던 리스트 위치, 정렬·필터, 스크롤이 그대로 복원된다. | **필터·스크롤 초기화** — 뒤로 갈 시 목록 최상단으로 이동해, 필터까지 풀려 처음부터 다시 설정해야 한다. |

## UXPT_NAV_3 — 닫기

> **패턴 태그**: Frictionless

닫기는 현재 오버레이, 모달, 바텀시트, 팝업 프로세스를 종료하는 장치입니다. 뒤로 가기가 이전 맥락 복귀라면, 닫기는 현재 흐름 종료입니다.

### 규칙

| 규칙 ID | 핵심 제약 | 설명 | 예시 |
|---------|---------|------|------|
| `UXPT_NAV_3_RULE_1` | 오버레이·독립 태스크 종료에만 사용 | 일반 이동이 이전 화면 이동에 기준을 닫기로 해서는 안 된다. | 전체 화면 이동에 닫기 버튼 사용 금지 |
| `UXPT_NAV_3_RULE_2` | 위치는 우측 상단 고정, 플랫폼 관습 준수 | 고객이 종료 옵션을 찾기 위해 화면을 스캔하지 않도록 일관된 위치에 있어야 한다. | Android·iOS 관습 동일하게 우측 상단 |
| `UXPT_NAV_3_RULE_3` | 데이터 손실 가능성 있는 화면: 닫기 전 저장 여부 확인 필수 | 결제 흐름에서 서비스 이탈 전에 확인해야 한다. 정보를 입력하다 닫기를 눌렀을 때 확인 없이 닫히면 고객이 모든 입력을 잃고 다시 해야 한다. | `'그래도 닫으시겠어요?'` 확인 다이얼로그 |
| `UXPT_NAV_3_RULE_4` | 닫은 이후 이동 위치는 사전 정의된 기준 화면으로 고정 | 어디서 닫든 랜덤하게 이동하지 않도록 기준을 사전에 정해야 한다. 어디서 닫든 어디로 이동하는지 일정하지 않으면 고객이 닫기를 누르기 전에 결과를 예측하기 어렵다. | 닫기 후 → 항상 홈 or 직전 리스트 중 사전 정의한 기준 화면 |

### Do / Don't

| Do ✅ | Don't ❌ |
|-------|---------|
| **손실 방지 확인 안내** — 종료 전 시스템이 진행 상태를 보호해 닫기 전 다음 행동을 묻는다. | **확인 없이 즉시 닫힘** — 다단계 입력 화면에서 X를 누르면 경고 없이 모든 입력이 사라진다. |
| `'그래도 닫으시겠어요?'` → 계속 작성 / 닫기 | X 버튼 클릭 시 경고 없이 전체 입력 초기화 |

### 시나리오 — 상황별 적용 방식

| 상황 | 닫기 동작 | copy |
|------|---------|------|
| 다단계 입력 중 닫기 시도 | 저장 여부 확인 다이얼로그 표시 | `'다음에 이어서 하시겠어요? 지금까지 입력하신 정보는 저장됐어요. 홈에서 언제든 이어서 완료할 수 있어요.'` |
| 진행 상태 없는 오버레이 닫기 | 즉시 닫힘 (확인 없음) | — |
| 닫기 후 이동 위치 | 사전 정의된 기준 화면 (홈 or 직전 리스트) | — |
