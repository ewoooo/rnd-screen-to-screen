# UXPT_PRC — Processing Feedback System

---

## UXPT_PRC_1 — 진행 단계 표시

### 개요

전체 태스크 흐름에서 현재 단계와 남은 단계를 항상 인지할 수 있도록 해야 합니다.

### 규칙 — UXPT_PRC_1_RULE_1

현재 단계와 전체 단계 구조를 함께 제공해야 합니다.

| 항목 | 내용 |
|------|------|
| 금지 | 단계 표시 없이 입력만 나열하면 고객이 전체 과정이 얼마나 남았는지 알 수 없어 중단을 고려합니다. |
| 방식 | `'2/4 단계'` + 현재 단계명을 함께 표시해야 합니다. |

### 규칙 — UXPT_PRC_1_RULE_2

진행 상태는 시각적으로 명확히 구분해야 합니다.

| 항목 | 내용 |
|------|------|
| 원칙 | 현재 단계와 상태가 시각적으로 분리되어야 합니다. |
| 방식 | 완료 단계는 채워진 색상, 현재 단계는 강조 상태, 미완료 단계는 빈 상태로 처리하여 고객이 전체 흐름에서 현재 위치를 파악합니다. |

### 규칙 — UXPT_PRC_1_RULE_3

고객이 남은 과정을 예측할 수 있어야 합니다.

| 항목 | 내용 |
|------|------|
| 원칙 | 다음 단계 요약 내용을 함께 표시하는 것이 좋습니다. |
| 설명 | 다음 단계가 `'결제 단계'`처럼 다음에 무엇을 해야 하는지 고지하면 고객이 부담 없이 다음 단계 진입을 준비합니다. |

### Do / Don't

| Do ✅ | Don't ❌ |
|-------|---------|
| stepper로 전체 흐름을 표시하여 현재 위치와 남은 단계가 한눈에 보이도록 한다. | 단계 표시 없이 다단계 흐름을 진행하여 `'몇 단계 더 남았지?'`를 고객이 매번 추측하게 만든다. |

### 시나리오 — 상황별 적용 방식

| 상황 | 단계 표시 방식 | 비고 |
|------|--------------|------|
| 주문 흐름 (4단계) | `1/4` 정보 확인 → `2/4` 할인 적용 → `3/4` 그룹원 초대 → `4/4` 납부 | 각 단계 상단 stepper 고정 |
| 그룹원 초대 (2단계) | `1/2` 혜택 선택 → `2/2` 혜택 받을 분 선택 | — |
| 초대 2단계 이상이 세분화되는 경우 | 상단에 진도를 표시하여 고객이 진행 상황을 지속 파악하며 태스크를 행할 수 있도록 합니다. | — |

## UXPT_PRC_2 — 처리 중 상태 설명

### 개요

어떤 동작이 일어나고 있는지를 고객 기준으로 설명합니다. 고객은 무엇이 처리 중인지, 언제 끝나는지, 결과로 무엇을 받게 되는지를 알아야 기다릴 수 있습니다.

### 규칙 — UXPT_PRC_2_RULE_1

현재 어떤 처리가 진행 중인지 고객 언어로 명시해야 합니다.

| 항목 | 내용 |
|------|------|
| 금지 | `'처리 중'`, `'대기 중'` 같은 기술 용어 대신 고객 표현을 사용해야 합니다. |
| 방식 | `'결제를 확인하고 있어요'`, `'대기 중'` 대신 `'신청을 접수하고 있어요'` 처럼 처리 내용이 무엇인지 고객이 이해하는 표현을 사용합니다. |

### 규칙 — UXPT_PRC_2_RULE_2

완료 시 제공될 결과를 사전에 안내해야 합니다.

| 항목 | 내용 |
|------|------|
| 원칙 | 고객이 기다리는 상태가 무엇인지 미리 안내해야 합니다. |
| 방식 | `'분석이 끝나면 나에 맞는 요금제를 추천해 드립니다'` 처럼 기다리는 결과를 먼저 제시하여 고객이 기다릴 이유를 납득합니다. |

### 규칙 — UXPT_PRC_2_RULE_3

예상 시간 또는 처리 범위를 함께 제공해야 합니다.

| 항목 | 내용 |
|------|------|
| 금지 | 시간 안내 없이 계속 기다리면 고객이 언제 처리가 끝나는지 판단하지 못하고 포기하거나 이탈합니다. |
| 방식 | `'확인까지 약 3초'`, `'1~2분 이내'` 형태로 표현해야 합니다. |

### 규칙 — UXPT_PRC_2_RULE_4

처리 내용과 결과가 함께 전달돼야 고객이 기다릴 이유를 납득할 수 있습니다.

| 항목 | 내용 |
|------|------|
| 금지 | 내용만 있고 결과 없거나, 결과만 있고 내용이 없으면 신뢰를 주지 못합니다. |
| 방식 | `'사용 패턴을 분석하고 있어요'(내용)` + `'요금제를 추천해 드립니다'(결과)`를 함께 제공해야 고객이 현재 상황과 기다릴 이유를 납득합니다. |

### Do / Don't

| Do ✅ | Don't ❌ |
|-------|---------|
| 무엇을 하는지(목적) + 결과 형태 + 예상 시간을 함께 전달한다. | 아무 설명 없이 스피너만 표시하여 무엇을 처리 중인지, 언제 끝나는지, 무엇을 받게 되는지 고객은 아무것도 알 수 없게 한다. |

#### Do 예시
```
요금제를 변경하고 있어요
약 10초 소요됩니다
```

## UXPT_PRC_3 — 미완료 입력 안내

### 개요

필수 입력이 완료되지 않은 상태에서 CTA를 차단하지 않고, 고객이 버튼을 탭했을 때 무엇이 부족한지 즉시 알 수 있도록 안내해야 합니다.

### 규칙 — UXPT_PRC_3_RULE_1

필수 입력이 완료되지 않았을 때 CTA는 비활성화가 아닌 낮은 강조 상태로 유지해야 합니다.

| 항목 | 내용 |
|------|------|
| 금지 | 버튼을 완전 비활성화하면 고객에게 이유를 전달하지 않아 탭하려는 의도를 방해합니다. |

### 규칙 — UXPT_PRC_3_RULE_2

미완료 상태의 CTA를 탭했을 때 어떤 항목을 채워야 하는지 즉시 안내해야 합니다.

| 항목 | 내용 |
|------|------|
| 방식 | `'먼저 비밀번호를 입력해 주세요'` 처럼 미완료 필드를 특정하여 안내하는 방식이어야 합니다. |

### 규칙 — UXPT_PRC_3_RULE_3

미완료 항목이 여러 개인 경우 화면 순서 기준으로 첫 번째 항목부터 순차적으로 안내해야 합니다.

| 항목 | 내용 |
|------|------|
| 방식 | 여러 항목을 한 번에 나열하기보다 첫 번째 항목에 집중하여 안내하고 해결 후 연속적으로 다음 미완료 항목을 안내합니다. |

### Do / Don't

| Do ✅ | Don't ❌ |
|-------|---------|
| 버튼 선택이 가능하며 탭 시 입력이 필요한 필드를 강조하여 안내한다. | 이유 없이 버튼만 차단하여 왜 진행할 수 없는지 안내가 전혀 없어 고객이 스스로 원인을 찾아야 한다. |

#### Do 예시
```
홍길동
010-1234-5678
[비밀번호를 입력해 주세요.] ← 강조
[제출하기] (낮은 강조 상태, 탭 가능)
```
